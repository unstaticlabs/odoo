# Receipt recovery action-risk review

Receipt recovery remains ordinary owner or Accounting Manager work. Public
recovery methods validate expense access, ownership or manager authority,
company, draft state and generation before attaching a receipt. Website
handoff GET is read-only; its separate CSRF-protected POST records the opening.
Host and pattern activation/blocking are the feature's Accounting Manager
governance workflow. Learned metadata requires a private identity sentinel;
client-provided context values do not authorize changes.

Queue dispatch executes an existing, locked, enqueued UUID using the persisted
originating-user recordset. It is operational, not read-only or unreachable.
Queue function/channel configuration uses the central protected CRUD guard.
Changing a job's execution user or company requires the semantic
`queue_job_authority` capability. OCA's in-process identity sentinel permits
worker persistence without granting RPC callers that exemption. Delegated
business operations retain their own accounting and access controls.

Receipt evidence deletion is protected in addition to native deny-unlink ACLs.
Private learning, retry, generation and worker bookkeeping have explicit
reachability evidence. Inherited native helpers are classified only where the
method and runtime implementation digest match a reviewed implementation;
their exact equivalence or behavioral rationale is retained per action in the
policy. Sparse-field metadata writes preserve the existing protected field
authority boundary and add only restrictions on changing storage or names.

The focused receipt suite covers forged contexts, caller/company boundaries,
queue authority, stale jobs, blocked hosts, duplicate attachments and manual
receipt supersession. The HTTP suite covers owner-bound handoff and CSRF.
Service tests run with offline fixtures, including a Chromium download under
the production sandbox restrictions. Inventory refresh does not substitute
for executing these tests and comparing the exact installed registry.

The merged receipt upload widget can appear outside the expense form header.
Both read-only expense roles now remove that widget wherever it appears.
The `hr.expense.get_view` implementation digest was refreshed for this restriction;
its classification and permission grants are unchanged. The reviewer test also
calls `attach_document` directly and verifies denial and preservation of the
existing main attachment.
